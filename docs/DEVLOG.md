# SoundTheSpire 开发记录

## 理念

SoundTheSpire 不是"把屏幕读出来"。目标是用多维度的听觉信息构建对局势的理解，像听一首歌：

- **音高**、**响度**、**音色**（电吉他、钢琴、铜管……）、**声像**（左右位置）、**节奏**都是信息通道。
- 面向盲人玩家，以及不想盯着屏幕的玩家；操作以键盘、手柄为主。
- 只表达明眼玩家在屏幕上能看到的信息，不多透露（例如隐藏意图保持模糊）。

参考：[Say the Spire 2](https://github.com/bradjrenshaw/say-the-spire2)（以朗读为主的无障碍 mod，可借鉴其补丁点和导航思路）。

## 声音设计规则（已确定）

### 敌人意图乐句

- **何时播放**：**每个玩家回合开始**播放"回合汇总"（见下）；回合中**选中**某个敌人时播放它的意图（键盘/手柄焦点、鼠标悬停、出牌瞄准都算），会打断正在播放的汇总。`R` 重听汇总。
- **引子**：全体播放前先有一小节小号 C 调 `1 5`（C4 四分音符 = 0.25 小节，G4 附点二分音符 = 0.75 小节；独立通道、居中），表明"接下来是对方的战斗意图"。选中单只不加引子。
- **每只怪时长相同**：全体播放时每只怪占同样数量的整小节（默认一小节 = 2 秒），乐句从小节开头开始，不足部分用空拍补齐。任何一只怪需要超过一小节（如 10 段攻击），所有怪都一起放宽到同样的小节数。
- **乐器 = 哪个敌人，电吉他优先给大怪**：按强度排序分配，顺序：失真吉他、铜管、弦乐、方波主音、管风琴。强度 = 主怪优先于随从（游戏的 `IsPrimaryEnemy` / `IsSecondaryEnemy`），再按生命上限从高到低，最后按编号。
  - 一场战斗内乐器固定，其他敌人死亡不会让乐器互换；死亡腾出的乐器给之后新出现的敌人（如分裂出来的史莱姆），新来者之间也按强度排。
  - 已验证：三史莱姆中型史莱姆 = 吉他；骑士精英生命最高的连枷骑士 = 吉他；同族 Boss 神官 = 吉他、信徒（随从）= 铜管/弦乐；女王 Boss 女王 = 吉他、聚合体 = 铜管。
- **声像 = 屏幕位置**。
- **攻击**：伤害越高越**低沉有力**，越低越**轻柔**。按游戏攻击图标的 5 档总伤害（<5, <10, <20, <40, 40+）：

  | 档 | 音区 | 力度 | 声部 |
  |---|---|---|---|
  | 1 | C5 | 45 | 单音 |
  | 2 | E4 | 62 | 五度 |
  | 3 | G3 | 82 | 强力和弦（根、五、八） |
  | 4 | C3 + 低八度 | 104 | 三音 |
  | 5 | E2 + 低八度 | 124 | 四音 |

  单段攻击越重时值越长。
- **攻击不用鼓**：打击乐没有明确音高，会让伤害档位难以分辨。
- **多段攻击**：强力和弦扫弦（低到高下扫）。4/4 拍、120 BPM 为标准，一次多段攻击默认约一小节（敌人数 × 段数总量不会太大）。每段一下、每下满一格。`1` = 开放扫，`x` = 闷音扫（力度 -20），空格只是听感分组、不占时间。

  | 段数 | 节奏型 | 网格 |
  |---|---|---|
  | 2 | `11` | 八分 |
  | 3 | `1xx` | 八分三连音 |
  | 4 | `1xxx` | 八分 |
  | 5 | `1xxx 1` | 八分 |
  | 6 | `1xx 1xx` | 八分三连音 |
  | 7 | `1xx1 xx1` | 八分 |
  | 8 | `1xx1 xx1x` | 八分 |
  | 9 | `1xx 1xx 1xx` | 八分三连音 |
  | 10 | `1xx1 xx1x 11` | 八分 |

  超过 10 段：先演奏完整的 8 段小节，余数用对应节奏型（如 12 = 8 + `1xxx`）。
- **防御**：低长音；**增益**：上行琶音；**减益**：下行琶音；**隐藏/未知/其他**：一个闷音。

### 回合汇总：对方意图 + 防御端状况

- **时机**：所有回合开始效果（遗物、抽牌、充能球、自动打出）结算完、玩家可以操作的那一刻（游戏的 `CombatManager.TurnStarted` 事件），第 1 回合即"开局遗物触发完成后"。
- **顺序**：小号引子 → 全体意图 → 一小节钢琴"防御端状况"，接在意图后的小节线上。
- **防御端状况**，比较"预计护甲"（见下）和来袭伤害：

  | 情况 | 乐段 |
  |---|---|
  | 预计护甲 ≥ 来袭 | sus4 → C 大三（与"压力解决"相同） |
  | 0 < 预计护甲 < 来袭 | sus4（C F G）悬着不解决 |
  | 完全没有防御（预计护甲 0，有来袭） | 不和谐：C D♭ G♭ 一拍 → B C F 附点二分（与引子同节奏） |
  | 没有来袭攻击 | C 大三 |

### 预计护甲：不操作也会得到的防御

- 防御端按"玩家什么都不做、直接结束回合时，敌人出手那一刻拥有的护甲"计算：当前护甲 + 所有回合结束自动加护甲的来源。回合汇总、"压力解决"判断、`sts_state` 都用它。
- 来源（从游戏的回合结束钩子中逐个找出）：
  - 奥利哈钢 / 伪奥利哈钢：护甲为 0 时 +6 / +3（游戏在最早的回合结束钩子里检查，先于其他来源）。
  - 镀层（护喉甲等给的 `PlatingPower`）：+层数。
  - 斗篷扣：每张手牌 +1。
  - 涟漪盆：本回合没打出攻击牌时 +4。
  - 冰霜充能球：每个 +被动值（含集中），触发次数走游戏自己的计算（金线缆让第一个球多触发一次）。
- 每个数值都经过游戏的 `Hook.ModifyBlock`，敏捷/虚弱等修正与实际结算一致。已验证：预计 19，结束回合后实际护甲 19。
- 手牌里"回合结束在手中"的卡（灼伤等）都不加护甲，不在列表中。

### 护甲：解决防御压力

- 护甲本身有游戏自带的基础音效，**不对每次加护甲额外发声**。
- 只在"防御压力被解决"的那一刻加一个乐段：玩家回合中，状态从"来袭攻击伤害 > 预计护甲"变为"来袭 ≤ 预计护甲"时，钢琴 sus4（C F G，一拍）解决到 C 大三（C E G C，两拍），C 调，与意图引子同调。来袭 = 所有存活敌人攻击意图的总伤害，与图标数字一致。
- **不论以什么方式解决都算**：加护甲、杀死攻击者、施加虚弱、敌人意图改变……实现上每帧比较预计护甲与来袭（`DefenseMonitor`），不依赖具体事件。
- 回合汇总播放时以当时状态为基准，所以回合开始遗物给的护甲体现在汇总里，不会再单独触发"解决"；敌方回合不检测。
- 把敌人全部消灭是战斗胜利，不播放。已挡满后继续加护甲：不发声。

### 待定

- 防御音色与"低沉 = 重攻击"冲突，待定（候选：柔和中音区长音 / 高音区护盾光泽 / 不变）。
- 鼠标划过敌人会打断回合开始的全员意图（悬停也算选中）。是否让鼠标悬停不打断、只有键盘/手柄焦点打断，待定。
- 超过 10 段的处理方式（目前：整小节 + 余数）待试听确认。
- 非吉他乐器的"闷音"只是弱奏，是否多段统一用吉他，未定。
- 预计护甲未扣除回合结束时的自伤（如手中灼伤会先吃掉护甲），是否计入待定。冰霜充能球没有控制台命令可测，只经过代码核对。

## 架构

```
SoundTheSpire.dll（常驻加载器，SoundTheSpireCode/）     SoundTheSpire.Hot.dll（可热重载，SoundTheSpire.Hot/）
├─ MainFile          mod 入口、依赖解析                    ├─ HotEntry          IHotModule 实现，F8/R 按键
├─ Core/MainThread   每帧主线程调度                        ├─ Combat/CombatReader   读取敌人、意图、屏幕位置
├─ Core/HotModuleHost  加载/替换热模块                     ├─ Combat/IntentAnnouncer 回合汇总（TurnStarted）/选中触发
│                                                          ├─ Combat/PassiveDefense, DefenseMonitor  预计护甲、压力解决
├─ Core/ConsoleRegistry 把热模块命令注入控制台             ├─ Audio/IntentMotif, BlockMotif   意图、防御端 → 音符
├─ Core/DebugBridge  127.0.0.1:47800 外部命令（DEBUG）     ├─ Audio/Midi, SoundTest
├─ Audio/SynthEngine MeltySynth → Godot 音频流（独立线程） └─ Commands/           场景与试听命令
└─ Commands/HostCommands  sts_status, sts_reload
```

- **合成**：MeltySynth + GeneralUser GS SoundFont（`scripts/fetch-assets.ps1` 下载，不入库）。游戏自身音效走 FMOD，本 mod 走 Godot 的 `AudioStreamGenerator`，两者并行。渲染在独立线程上，加载卡顿不再欠载。事件按采样时间排程。
- **热重载**：热模块按字节读入新的 `AssemblyLoadContext`（不锁文件）。重载时先检查新程序集，再撤销旧代的 Harmony 补丁、控制台命令、帧回调，重置合成器，然后装入新代。旧程序集不卸载（每次几百 KB，开发期可忽略）。热模块编译时引用 mods 目录里**已部署**的加载器，加载器接口变更会在编译期报错。
- **数据与声音分离**：`CombatReader` 是唯一接触游戏模型的地方，输出 `EnemyInfo` / `IntentInfo`；声音代码只看这些结构，游戏更新时影响范围可控。

### 关键游戏 API（v0.107.1）

- 意图在 `CombatManager.StartTurn` 中 `enemy.PrepareForNextTurn` 掷出。`CombatManager.TurnStarted` 事件在玩家回合所有开始效果（`AfterPlayerTurnStart` 钩子、抽牌、充能球、自动打出）之后、进入出牌阶段时触发，热模块在 `Load`/`Unload` 中订阅/退订。`ICombatState.RoundNumber` 第一回合为 1。
- 回合结束加护甲的钩子顺序：`BeforeSideTurnEndVeryEarly`（奥利哈钢检查护甲）→ `BeforeSideTurnEndEarly`（镀层）→ `BeforeSideTurnEnd`（奥利哈钢、斗篷扣、涟漪盆）；充能球由 `OrbQueue.BeforeTurnEnd` 触发。
- 选中：`NCreature.OnFocus`（私有）同时处理 Hitbox 的焦点和鼠标进入，出牌瞄准也经过这里。
- 攻击伤害：`AttackIntent.GetSingleDamage(targets, owner)` 已含力量/虚弱等修正，`Repeats` 为段数。
- 控制台：`DevConsole` 构造时扫描 mod 程序集中的 `AbstractConsoleCmd`，存入私有 `_commands`。
- 游戏只加载 `mods/<id>/<id>.dll`（`LoadFromAssemblyPath`，会锁文件）。

## 开发流程

环境：.NET SDK（`winget install Microsoft.DotNet.SDK.10`），PowerShell 中需 `$env:PATH = "C:\Program Files\dotnet;" + $env:PATH`。反编译参考：`ilspycmd -p -o .\decompiled\sts2 sts2.dll`（`decompiled/` 不入库）。

| 场景 | 命令 |
|---|---|
| 改了加载器（`SoundTheSpireCode/`） | `.\scripts\dev-restart.ps1`（关游戏、构建、启动、等待调试桥） |
| 改了热模块（`SoundTheSpire.Hot/`） | `.\scripts\hot.ps1 [-Then cmd, ...]`（约 3.5 秒，不离开当前战斗） |
| 发送单条控制台命令 | `.\scripts\sts.ps1 <命令>` |
| 跑场景脚本 | `.\scripts\scenario.ps1 scripts\scenarios\<文件>.txt` |

场景脚本语法：每行一条控制台命令；`#` 注释；`sleep <秒>`；`wait menu|run|combat`。

| 场景 | 内容 |
|---|---|
| `attack-tiers.txt` | 新开局进三史莱姆战斗，设 4 / 15 / 8×3 攻击，播放全体再逐个 |
| `intent-kinds.txt` | 新开局，同一敌人依次 5 档攻击、防御、增益、减益、多段 |
| `attack-ladder.txt` | 需已在战斗中：5 档单段 + 两种 4 段 |
| `multi-hit.txt` | 需已在战斗中：2–10 段、12 段，以及轻重 4 段对比 |
| `block-resolve.txt` | 需已在三史莱姆战斗中：来袭 22，护甲 10 → 20 → 25（解决）→ 30 |
| `defense-resolve.txt` | 需已在一局中：新开三史莱姆战斗，依次用杀死攻击者、虚弱、意图变轻三种方式解决压力 |
| `lineup-bars.txt` | 需已在三史莱姆战斗中：每只怪一小节，再演示一只 10 段时全体放宽为两小节 |
| `passive-defense.txt` | 需已在一局中：新开战斗（开局汇总为不和谐乐段），加奥利哈钢/镀层/涟漪盆/斗篷扣，部分覆盖 → 完全覆盖 |
| `passive-defense-actual.txt` | 需已在一局中：预计护甲与结束回合后的实际护甲对照 |

mod 控制台命令：

| 命令 | 所在 | 作用 |
|---|---|---|
| `sts_status` | 加载器 | 合成器状态、主总线峰值（无法监听时用来确认有声音）、热模块代数 |
| `sts_reload` | 加载器 | 重载热模块 |
| `sts_run [角色] [种子]` | 热模块 | 开新局（不存档） |
| `sts_menu` | 热模块 | 回主菜单 |
| `sts_intent <idx\|all> attack 伤害 [段数] \| defend 量 \| buff 量 \| debuff 量` | 热模块 | 设定敌人意图 |
| `sts_state` | 热模块 | 打印局面（含预计护甲明细、每只怪的乐器、是否主怪） |
| `sts_endturn` | 热模块 | 结束本回合（同"结束回合"按钮） |
| `sts_intents [idx]` | 热模块 | 无参数播放回合汇总（同 `R`），带参数播放单个敌人 |
| `sts_test` | 热模块 | 合成器测试：钢琴左、吉他中、鼓右 |

调试路径：日志 `%APPDATA%\SlayTheSpire2\logs\godot.log`；mod 目录 `Steam\steamapps\common\Slay the Spire 2\mods\SoundTheSpire\`。

## 路线图

v1（战斗中的"敌人要做什么、我挡不挡得住"）：

1. ✅ 敌人意图乐句
2. ✅ 护甲：只在护甲首次足以挡住来袭伤害时播放"压力解决"乐段
3. ⬜ 敌人回合的结果音：完全格挡 / 格挡被打破 / 未格挡
4. ⬜ 试玩调音

v1 不做：朗读、手牌信息、导航、地图、商店、事件、多人、设置界面。
