# SoundTheSpire 开发记录

## 理念

SoundTheSpire 不是"把屏幕读出来"。目标是用多维度的听觉信息构建对局势的理解，像听一首歌：

- **音高**、**响度**、**音色**（电吉他、钢琴、铜管……）、**声像**（左右位置）、**节奏**都是信息通道。
- 面向盲人玩家，以及不想盯着屏幕的玩家；操作以键盘、手柄为主。
- 只表达明眼玩家在屏幕上能看到的信息，不多透露（例如隐藏意图保持模糊）。

参考：[Say the Spire 2](https://github.com/bradjrenshaw/say-the-spire2)（以朗读为主的无障碍 mod，可借鉴其补丁点和导航思路）。

## 声音设计规则（已确定）

### 敌人意图乐句

- **何时播放**：**每个玩家回合开始**播放"回合汇总"（见下）；回合中**选中**某个敌人时播放它的意图（键盘/手柄焦点、鼠标悬停、出牌瞄准都算），会打断正在播放的汇总。焦点保持在同一敌人上时，主旋律作为连续声部跨小节延伸；鼓组只在首次选中或意图内容改变时触发。失焦或转移焦点停止连续声部。`R` 重听汇总。
- **不播放引子**：全体汇总直接从第一只怪开始；有逐曲 FMOD 时钟时，第一只怪量化到下一条小节线。
- **每只怪时长相同**：全体播放时每只怪占同样数量的整小节（未适配曲目默认一小节 = 2 秒；瀑布巨兽按原曲 5/8 小节），乐句从小节开头开始，不足部分用空拍补齐。任何一只怪需要超过一小节（如 10 段攻击），所有怪都一起放宽到同样的小节数。
- **乐器 = 哪个敌人**：未适配曲目按强度排序使用失真吉他、铜管、弦乐、方波主音、管风琴；瀑布巨兽专用管弦表为圆号、拨弦弦乐、大提琴、双簧管。强度 = 主怪优先于随从（游戏的 `IsPrimaryEnemy` / `IsSecondaryEnemy`），再按生命上限从高到低，最后按编号。
  - 一场战斗内乐器固定，其他敌人死亡不会让乐器互换；死亡腾出的乐器给之后新出现的敌人（如分裂出来的史莱姆），新来者之间也按强度排。
  - 已验证：三史莱姆中型史莱姆 = 吉他；骑士精英生命最高的连枷骑士 = 吉他；同族 Boss 神官 = 吉他、信徒（随从）= 铜管/弦乐；女王 Boss 女王 = 吉他、聚合体 = 铜管。
- **声像 = 屏幕位置**。
- **攻击**：伤害越高越**低沉有力**，越低越**轻柔**。按游戏攻击图标的 5 档总伤害（<5, <10, <20, <40, 40+）：

  | 档 | 音区 | 力度 | 声部 |
  |---|---|---|---|
  | 1 | C5 | 45 | 单音 |
  | 2 | E4 | 62 | 五度 |
  | 3 | G3 | 82 | 强力和弦（根、五、八） |
  | 4 | C3 + 低八度 | 104 | 三音 |
  | 5 | E2 + 低八度 | 124 | 四音 |

  单段攻击越重时值越长。
  瀑布巨兽曲改用 B 小调五声音区：B4、D4、F#3、B2、D2；高伤是调内三和弦，超高伤再加低八度根音。
- **单段攻击不用鼓**：明确音高与和弦厚度仍是伤害档位的主体。
- **多段攻击**：管弦声部扫弦（低到高下扫）上叠加 Profile 配置的 GM 鼓组；轻到重依次为三角铁、踩镲、军鼓、通鼓、底鼓+吊镲。未适配曲目以 4/4、120 BPM 为回退；已适配曲目跟随 FMOD 拍点。每段一下、每下满一格。`1` = 开放扫/开放击，`x` = 闷音扫/闷击，空格只分组、不占时间。

  | 段数 | 节奏型 | 网格 |
  |---|---|---|
  | 2 | `11` | 八分 |
  | 3 | `1xx` | 八分三连音 |
  | 4 | `1xxx` | 八分 |
  | 5 | `1xxx 1` | 八分 |
  | 6 | `1xx 1xx` | 八分三连音 |
  | 7 | `1xx1 xx1` | 八分 |
  | 8 | `1xx1 xx1x` | 八分 |
  | 9 | `1xx 1xx 1xx` | 八分三连音 |
  | 10 | `1xx1 xx1x 11` | 八分 |

  超过 10 段：先演奏完整的 8 段小节，余数用对应节奏型（如 12 = 8 + `1xxx`）。
- **防御**：低长音；**增益**：上行琶音；**减益**：下行琶音；**隐藏/未知/其他**：一个闷音。

### 回合汇总：对方意图 + 防御端状况

- **时机**：所有回合开始效果（遗物、抽牌、充能球、自动打出）结算完、玩家可以操作的那一刻（游戏的 `CombatManager.TurnStarted` 事件），第 1 回合即"开局遗物触发完成后"。
- **顺序**：全体意图 → 一小节钢琴"防御端状况"，接在意图后的小节线上。
- **防御端状况**按**受伤** = 来袭 − 预计护甲（见下）分层，界线与攻击分层相同（< 5、< 10、< 20、< 40、40+），乐句从完全不协和到协和，力度随受伤加重：

  | 受伤 | 乐段 |
  |---|---|
  | 0（挡住） | sus4 → C 大三（解决） |
  | 1–4 | sus4 C F G，悬着 |
  | 5–9 | 减三和弦 C E♭ G♭ |
  | 10–19 | C G♭ B（三全音 + 大七度） |
  | 20–39 | C D♭ G♭（小二度 + 三全音） |
  | 40+ | 完全不协和：低 C + C D♭ G♭ 一拍 → 低 B + B C F 附点二分（与引子同节奏） |
  | 没有来袭攻击 | C 大三 |

  受伤分层与预计护甲是否为 0 无关：没有护甲但只受 3 点伤害仍是轻度的 sus4。
  瀑布巨兽曲中全部以 B 为中心，解决和弦为 B 小三和弦；5/8 按 2+3，出牌转换进入八分/十六分拍点队列。

### 预计护甲：不操作也会得到的防御

- 防御端按"玩家什么都不做、直接结束回合时，敌人出手那一刻拥有的护甲"计算：当前护甲 + 所有回合结束自动加护甲的来源。回合汇总、"压力解决"判断、`sts_state` 都用它。
- 来源（从游戏的回合结束钩子中逐个找出）：
  - 奥利哈钢 / 伪奥利哈钢：护甲为 0 时 +6 / +3（游戏在最早的回合结束钩子里检查，先于其他来源）。
  - 镀层（护喉甲等给的 `PlatingPower`）：+层数。
  - 斗篷扣：每张手牌 +1。
  - 涟漪盆：本回合没打出攻击牌时 +4。
  - 冰霜充能球：每个 +被动值（含集中），触发次数走游戏自己的计算（金线缆让第一个球多触发一次）。
- 每个数值都经过游戏的 `Hook.ModifyBlock`，敏捷/虚弱等修正与实际结算一致。已验证：预计 19，结束回合后实际护甲 19。
- 手牌里"回合结束在手中"的卡（灼伤等）都不加护甲，不在列表中。

### 护甲：防御端改判

- 护甲本身有游戏自带的基础音效，**不对每次加护甲额外发声**。
- 判定 = 受伤（来袭 − 预计护甲，最小 0），分层见上表。来袭 = 所有存活敌人攻击意图的总伤害，与图标数字一致。
- **毒死的敌人不计入来袭**：毒在敌人回合开始、行动之前结算。用游戏自带的 `PoisonPower.CalculateTotalDamageNextTurn()`（血条上的毒死预告，含加速剂多次触发与伤害修正），毒伤 ≥ 当前生命的敌人攻击不算。给敌人上致命毒也算一次改判。意图乐句照常播放该敌人的意图（屏幕上仍显示）。毒死后会复活的敌人（如 `ReattachPower`）本回合也不会再攻击，同样剔除。
- 厄运（`DoomPower`）在敌人自己回合**结束**时才杀，敌人已出手，不影响判定。
- **每次改判都发声**：受伤数值一变就播放其所在层的防御端乐段（与回合汇总末尾同一套）。同一层内的变化也发声（如受伤 15 → 12），这样每个操作都有反馈。
- **意图与防御是独立音频层**：敌人乐器/鼓组与玩家防御钢琴使用不同 MIDI 通道。防御改判只替换自己的钢琴连音，不再调用全局 `SynthEngine.Stop()`；保持焦点的连续意图旋律可与防御状态同时发声。敌人保持焦点时，防御钢琴通道音量由 Profile 的 `defenseVolume` 100 降到 `focusedDefenseVolume` 45，使意图/鼓组保持前景；失焦后恢复。
- **不论什么原因导致改判都算**：加护甲、杀死攻击者、施加虚弱、敌人意图改变、打出攻击牌让涟漪盆失效……实现上每帧重新判定（`DefenseMonitor`），不依赖具体事件。
- **出牌改善防御 = 转换**：一张牌（或一瓶药水）作为一个整体判定，从离开手牌到效果结束。期间的中途变化不单独发声；结束时若受伤比出牌前**减少**，播放一小节**连音转换**：出牌前状态的和弦一拍，直接连到出牌后状态的和弦三拍（同 sus4 → 大三的节奏）。共同音持续不重弹，其余音略微重叠，听起来是"变过去"而不是两段。代表和弦：受伤 1–4 层用各自和弦，5 层用带低音的冲突和弦，挡住用 C 大三；若增加，只播新状态；不变则不发声。原因不限于加护甲，打出攻击牌杀死攻击者也算。
  - **连续出牌连成一条线**：上一次转换的和弦还没松开时又有牌改善了防御，就从正在响的和弦直接连到新和弦，并把松开时间往后推三拍。连打三张防御会听到一条逐步走向解决的连音线。其他声音（意图、单个状态乐段）打断时线就断开（`LegatoLine.Interrupt`），下次重新开始。
  - 出牌窗口 = 牌在"打出区"牌堆中（离手后即进入，斗篷扣的手牌数在此刻就变了）或 `CombatManager.IsExecutingCardOrPotionEffect` 为真。
- 回合汇总播放时以当时判定为基准，所以回合开始遗物给的护甲体现在汇总里，不会再单独触发；敌方回合不检测。
- 把敌人全部消灭是战斗胜利，不播放。受伤已是 0 后继续加护甲：受伤不变，不发声（游戏自带加护甲音效）。

### 意图遮罩：用耳朵分辨

- 隐藏游戏里敌人的意图图标（含伤害数字），引导玩家只靠声音判断意图。**默认开启**，`F9` 或 `sts_veil [on|off]` 切换。
- 实现：每帧把存活敌人的 `NCreature.IntentContainer` 设为不可见。游戏自己只用透明度做意图淡入淡出、只在死亡时把容器设为不可见，所以遮罩接管可见性；关闭时只恢复自己藏的、且敌人仍存活的容器。热模块卸载时自动恢复。
- **意图解释也遮住**：鼠标移到敌人身上时，意图说明（原标题就是意图类型，如"攻势"）改为一条"**意图**：你需要用声音判断意图"。一个敌人有多个意图也只显示这一条，不透露意图数量。能力等其他提示照常显示。
  - 意图提示由 `AbstractIntent.GetHoverTip` 生成，但它很短，被 JIT 内联进调用方，直接打补丁无效。改为拦截所有悬浮提示的显示入口 `NHoverTipSet.CreateAndShow`，按提示 Id（`LocString with Title=intents.` 开头）识别意图提示，且只处理属于敌人节点的提示。

### 数值遮罩

- 跟随同一个遮罩开关（F9 / `sts_veil`）隐藏数值：
  - 所有角色血条上的生命数字和护甲数字（血条本身、护甲盾牌图标保留，能看出有没有护甲，看不到多少）。
  - 浮动的伤害数字、治疗数字（"已格挡"是文字，保留）。
  - 顶栏玩家血量：只在战斗中隐藏，地图等场景照常显示。
  - **卡牌描述里的所有数值**（伤害、格挡、层数……）在战斗中替换为"?"。卡牌图鉴、战斗外牌组、奖励选牌照常显示：玩家在那里阅读、学习数值，进了战斗就只能靠声音。判定沿用游戏自己的"InCombat"：战斗进行中且牌在战斗牌堆里。左上角能量费用保留（出牌需要）。修正后的数值颜色（绿/红）仍可见。
- 卡牌文字在 `CardModel.GetDescriptionForPile`（带私有 `DescriptionPreviewType` 参数的重载，所有卡面文字都经过它）之后改写，只替换 BBCode 标签外的数字。切换时扫描场景里的 `NCard` 调 `UpdateVisuals` 重绘。
- 实现：血条每次刷新都会重设标签可见性，所以在 `NHealthBar.RefreshText` / `RefreshBlockUi` 之后再隐藏；伤害/治疗数字在 `_Ready` 时隐藏；顶栏每帧设置。热重载时界面已存在，加载和切换时扫描场景树找到已有的血条与顶栏并刷新。卸载时关闭遮罩，全部恢复。

### 声音教学关

- 只能从主菜单中央的原生"声音教学关"按钮（或主菜单下的 `sts_tutorial`）进入；按钮位于"时间线"与"设置"之间。它新开一局不存档的铁甲战士（种子 `LISTEN`），第一回合开始时布置教学。
- 正常游戏局内不显示入口，F10 已撤掉，局内执行 `sts_tutorial` 也会拒绝；教学关是独立单人局，不再从现有单人或多人局切入。
- `CombatWon` 标记教学胜利，`CombatEnded` 确认战斗清理完成；下一帧直接 `ReturnToMainMenu()`，不进入奖励、地图或下一幕。
- 只改教学局的布置，其余都是标准游戏：怪物血量照常生成，攻击目标、爆发结算、能量都不干预。不调用 `DebugRandomizeRng`，遭遇战随机数由固定教学种子决定。
- 四只有代表性的怪，从左到右由轻到重，都用自己原本的招式（数值随进阶由游戏决定）：
  - 小树枝史莱姆：撞击 4（轻攻击）。
  - 石盛碗虫：头槌 15，高进阶 16（重单段）。
  - 蜂群术士：蜂群 3×7，高进阶 3×8（多段）。
  - 瀑布巨兽：直接进入它自己的最后阶段（无限血量、不显示数字），看到就知道杀不死，只能防。本回合意图就是爆发 30，爆发后它自己死亡，战斗结束。
  - 开局受伤 70，结尾是完全不协和的撞击。
- 每个玩家的手牌：内核加速（0 费，+2 能量）、痛击（易伤）、四张本场 0 费的午夜（60 伤害；史莱姆、盛碗虫各一张，易伤的蜂群术士两张）、岿然不动（30 格挡挡住巨兽）。开局 3 能量 + 内核加速，够打痛击和岿然不动。
- 对话气泡**不解说、不教出牌**，只提问，让玩家自己探索；不再播放小号引子：
  1. 开场："每只怪都有自己的声音。音高好像代表了什么？"（提示里不出现数字，画面上看得到的不说）
  2. 变化（听完每只怪，或受伤第一次减少时）："最后那段和弦又响了。和弦好像代表了什么？"
  3. 解决（受伤为 0 时，随时触发）："和弦落下来了。这好像代表了什么？"
- 中途加入的怪在没有站位槽的遭遇战里没有位置，加入后重新调用游戏的 `PositionEnemies` 排一行（小怪在左、巨兽最右），回合汇总按屏幕横坐标排序，所以乐句也是由轻到重。

### 待定

- 鼠标划过敌人会打断回合开始的全员意图（悬停也算选中）。是否让鼠标悬停不打断、只有键盘/手柄焦点打断，待定。
- 超过 10 段的处理方式（目前：整小节 + 余数）待试听确认。
- 非吉他乐器的"闷音"只是弱奏，是否多段统一用吉他，未定。
- 预计护甲未扣除回合结束时的自伤（如手中灼伤会先吃掉护甲），是否计入待定。冰霜充能球没有控制台命令可测，只经过代码核对。
- 回合结束时对敌人的随机伤害（闪电充能球被动等）可能打死攻击者，目标随机，暂不计入。

## 架构

```
SoundTheSpire.dll（常驻加载器，SoundTheSpireCode/）     SoundTheSpire.Hot.dll（可热重载，SoundTheSpire.Hot/）
├─ MainFile          mod 入口、依赖解析                    ├─ HotEntry          IHotModule 实现，F8/R 按键
├─ Core/MainThread   每帧主线程调度                        ├─ Combat/CombatReader   读取敌人、意图、屏幕位置
├─ Core/HotModuleHost  加载/替换热模块                     ├─ Combat/IntentAnnouncer 回合汇总（TurnStarted）/选中触发
│                                                          ├─ Combat/PassiveDefense, DefenseMonitor  预计护甲、压力解决
│                                                          ├─ Combat/EncounterAnnouncer  遭遇身份、增援、状态始末播报
├─ Core/ConsoleRegistry 把热模块命令注入控制台             ├─ Audio/IntentMotif, BlockMotif   意图、防御端 → 音符
├─ Core/DebugBridge  127.0.0.1:47800 外部命令（DEBUG）     ├─ Audio/VoiceManifest, VoicePlayback  本地化 OGG 队列
│                                                          ├─ Audio/Midi, SoundTest
├─ Audio/SynthEngine MeltySynth → Godot 音频流（独立线程） └─ Commands/           场景与试听命令
└─ Commands/HostCommands  sts_status, sts_reload
```

- **合成**：MeltySynth + GeneralUser GS SoundFont（`scripts/fetch-assets.ps1` 下载，不入库）。游戏自身音效走 FMOD，本 mod 走 Godot 的 `AudioStreamGenerator`，两者并行。渲染在独立线程上，加载卡顿不再欠载。事件按采样时间排程。
- **热重载**：热模块按字节读入新的 `AssemblyLoadContext`（不锁文件）。重载时先检查新程序集，再撤销旧代的 Harmony 补丁、控制台命令、帧回调，重置合成器，然后装入新代。旧程序集不卸载（每次几百 KB，开发期可忽略）。热模块编译时引用 mods 目录里**已部署**的加载器，加载器接口变更会在编译期报错。
- **数据与声音分离**：`CombatReader` 是唯一接触游戏模型的地方，输出 `EnemyInfo` / `IntentInfo`；声音代码只看这些结构，游戏更新时影响范围可控。

### 关键游戏 API（v0.107.1）

- 意图在 `CombatManager.StartTurn` 中 `enemy.PrepareForNextTurn` 掷出。`CombatManager.TurnStarted` 事件在玩家回合所有开始效果（`AfterPlayerTurnStart` 钩子、抽牌、充能球、自动打出）之后、进入出牌阶段时触发，热模块在 `Load`/`Unload` 中订阅/退订。`ICombatState.RoundNumber` 第一回合为 1。
- 回合结束加护甲的钩子顺序：`BeforeSideTurnEndVeryEarly`（奥利哈钢检查护甲）→ `BeforeSideTurnEndEarly`（镀层）→ `BeforeSideTurnEnd`（奥利哈钢、斗篷扣、涟漪盆）；充能球由 `OrbQueue.BeforeTurnEnd` 触发。
- 选中：`NCreature.OnFocus`（私有）同时处理 Hitbox 的焦点和鼠标进入，出牌瞄准也经过这里。
- 战场语音：`CombatManager.CombatSetUp` 提前订阅状态事件，`CombatBegan` 播初始阵容，`CreaturesChanged` 检测中途新增敌人，参战单位的 `PowerApplied` / `PowerRemoved` 播可见 Buff / Debuff 的始末，`CombatEnded` 清队列。遭遇等级直接读 `EncounterModel.RoomType`；显示名来自当前本地化，但音频按稳定的 encounter / monster / power ID 索引。
- 攻击伤害：`AttackIntent.GetSingleDamage(targets, owner)` 已含力量/虚弱等修正，`Repeats` 为段数。
- 控制台：`DevConsole` 构造时扫描 mod 程序集中的 `AbstractConsoleCmd`，存入私有 `_commands`。
- 游戏只加载 `mods/<id>/<id>.dll`（`LoadFromAssemblyPath`，会锁文件）。

## 路线图

v1（战斗中的"敌人要做什么、我挡不挡得住"）：

1. ✅ 敌人意图乐句
2. ✅ 护甲：只在护甲首次足以挡住来袭伤害时播放"压力解决"乐段
